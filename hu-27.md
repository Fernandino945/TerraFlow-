Antes del código, tres aclaraciones que cambian el trabajo:

La URL estable ya la tienes. El dominio …ngrok-free.dev que usas es un dominio estático gratuito de ngrok, así que no necesitas comprar dominio ni crear un túnel con nombre de Cloudflare. La subtarea pasa a ser “mantener ese dominio y levantarlo junto con Docker”.
“Comandos” en el criterio se refiere solo a ingesta y heartbeat. El endpoint /api/valves/command lo usa el dashboard, no el nodo. Si le exiges la clave del nodo, el dashboard deja de poder abrir válvulas. Protegerlo requiere login de usuarios, que queda como trabajo futuro declarado.
Validar TLS en el ESP32 exige que el nodo tenga la hora correcta (NTP). Sin hora, los certificados parecen “aún no válidos” y la conexión falla. Por eso el firmware incluye sincronización de hora.
1. Backend

backend/app/core/config.py: agrega este campo dentro de tu clase Settings:

python
NODE_API_KEY: str = ""

Archivo nuevo backend/app/core/security.py:

python
import secrets
from typing import Optional
from fastapi import Header, HTTPException
from app.core.config import settings


async def require_node_key(x_api_key: Optional[str] = Header(default=None, alias="X-API-Key")):
    """Exige la clave del nodo. Si el servidor no tiene clave configurada, rechaza todo (falla cerrado)."""
    expected = settings.NODE_API_KEY
    if not expected:
        raise HTTPException(status_code=503, detail="NODE_API_KEY no configurada en el servidor")
    if x_api_key is None:
        raise HTTPException(status_code=401, detail="Falta la cabecera X-API-Key")
    if not secrets.compare_digest(x_api_key.encode(), expected.encode()):
        raise HTTPException(status_code=403, detail="API key invalida")

backend/app/api/sensors.py: ajusta el import y los dos decoradores.

2. Docker, .env y Git

Genera la clave (una sola vez; PowerShell):

powershell
$b = New-Object byte[] 32; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); ($b | ForEach-Object { $_.ToString("x2") }) -join ""

Si prefieres Python: python -c "import secrets; print(secrets.token_hex(32))".

Archivo .env en la raíz del repo (no va a Git):

NODE_API_KEY=pega_aqui_la_clave_generada

Archivo .env.example (este sí va a Git):

NODE_API_KEY=cambia_esta_clave

docker-compose.yml: en el servicio backend, dentro de environment:

yaml
      - NODE_API_KEY=${NODE_API_KEY}

.gitignore:

.env
firmware/**/secrets.h

Opcional: que el túnel de ngrok arranque con Docker (así un reinicio completo es un solo comando). Agrega este servicio y, en .env, las variables NGROK_AUTHTOKEN y NGROK_DOMAIN:

yaml
  ngrok:
    image: ngrok/ngrok:latest
    command: http --url=${NGROK_DOMAIN} nginx:80
    environment:
      - NGROK_AUTHTOKEN=${NGROK_AUTHTOKEN}
    depends_on:
      - nginx
    networks:
      - terraflow-net
    restart: unless-stopped

Verifica la sintaxis exacta en la documentación de ngrok: en versiones antiguas del cliente es --domain en vez de --url. Si prefieres seguir con el ngrok de tu PC, el comando equivalente es ngrok http --url=TU-DOMINIO 80.

Aplica todo con docker compose up -d --build.

3. Firmware

Archivo nuevo secrets.h (junto a sketch.ino; no va a Git):

cpp
#pragma once
#define WIFI_SSID    "tu_red_2_4ghz"
#define WIFI_PASS    "tu_clave_wifi"
#define BACKEND_BASE "https://tu-dominio.ngrok-free.dev"   // sin / al final
#define NODE_API_KEY "la_misma_clave_del_env"

Archivo secrets.example.h: igual que el anterior pero con valores de relleno. Este sí va a Git.

Archivo nuevo root_ca.h (es un certificado público, puede ir a Git):

cpp
#pragma once
const char* ROOT_CA_PEM = R"EOF(
-----BEGIN CERTIFICATE-----
PEGA_AQUI_EL_CERTIFICADO_RAIZ
-----END CERTIFICATE-----
)EOF";

Cómo obtener el certificado raíz: abre tu URL de ngrok en Chrome, haz clic en el candado, luego “La conexión es segura” y “El certificado es válido”. En la pestaña Detalles, elige el certificado de más arriba en la jerarquía y exporta en formato Base-64 (.cer). Abre ese archivo con un editor de texto y pega su contenido en root_ca.h. Si el emisor es Let’s Encrypt, también puedes bajar el raíz oficial desde la página de certificados de Let’s Encrypt. No pude confirmar qué autoridad usa ngrok, así que ve lo que muestra tu navegador.

Cambios en sketch.ino. Reemplaza el bloque de credenciales y URLs del inicio por:

cpp
#include "secrets.h"
#include "root_ca.h"
#include <time.h>

const char* ssid = WIFI_SSID;
const char* password = WIFI_PASS;
const char* INGEST_URL    = BACKEND_BASE "/api/sensors/ingest";
const char* HEARTBEAT_URL = BACKEND_BASE "/api/sensors/gateway/heartbeat";
const char* SENSOR_ID     = "sensor_zone_1";
bool timeSynced = false;

Agrega estas dos funciones antes de enviarLectura:

cpp
void sincronizarHora() {
  configTime(0, 0, "pool.ntp.org", "time.google.com");
  struct tm t;
  timeSynced = getLocalTime(&t, 10000);
  Serial.println(timeSynced ? "Hora sincronizada (NTP)" : "No se pudo sincronizar la hora");
}

bool prepararTls(WiFiClientSecure& client) {
  if (!timeSynced) return false;
  client.setCACert(ROOT_CA_PEM);
  return true;
}

En enviarLectura y en enviarHeartbeat, reemplaza client.setInsecure(); por:

cpp
  if (!prepararTls(client)) { Serial.println(" TLS: hora no sincronizada"); return -1; }

En ambas, justo después de http.addHeader("Content-Type", "application/json");, agrega:

cpp
    http.addHeader("X-API-Key", NODE_API_KEY);

En setup(), después de conectarWiFi();:

cpp
  if (WiFi.status() == WL_CONNECTED) sincronizarHora();

En loop(), justo después del bloque que reconecta el WiFi:

cpp
  if (WiFi.status() == WL_CONNECTED && !timeSynced) sincronizarHora();

Si el nodo no tiene hora, el heartbeat devuelve −1 y el failsafe local de HU-26 cierra la válvula. Es el comportamiento seguro.

Si usas el sketch de Wokwi, también necesita la cabecera X-API-Key, o el backend lo rechazará.

4. Pruebas

Define la clave en PowerShell ($k = "tu_clave") y usa curl.exe -i para ver el código HTTP. Prueba también contra http://localhost (Nginx) y contra tu dominio público.

#	Prueba	Comando o acción	Resultado esperado
1	Sin clave	curl.exe -i -X POST http://localhost:8000/api/sensors/gateway/heartbeat -H "Content-Type: application/json" -d "{}"	401
2	Clave inválida	El mismo, con -H "X-API-Key: incorrecta"	403
3	Clave válida	El mismo, con -H "X-API-Key: $k"	200 y desired_status
4	Ingesta con clave válida	curl.exe -i -X POST http://localhost:8000/api/sensors/ingest -H "Content-Type: application/json" -H "X-API-Key: $k" --data "@body.json" con un cuerpo válido	200
5	Regresión de validación	Igual que la 4, con humidity 150	422 (sigue funcionando)
6	Dashboard abierto	curl.exe -i http://localhost:8000/api/sensors/status	200 sin clave
7	Servidor sin clave configurada	Levanta el backend con NODE_API_KEY vacía	503 en ingesta y heartbeat
8	Nodo con clave correcta	Monitor Serie	HEARTBEAT -> 200 y HTTP 200 en las lecturas
9	Nodo con clave incorrecta	Cambia la clave en secrets.h y sube	403 en el Serial; con la válvula abierta, el failsafe local la cierra
10	TLS validado	Altera un carácter del certificado en root_ca.h y sube	El envío falla (código −1); no debe dar 200
11	URL estable	docker compose down, luego docker compose up -d y reinicia el túnel	El nodo reanuda el envío sin reprogramarse
12	Repo limpio	git status --ignored y git grep -n -I -i "password" -- firmware	secrets.h y .env aparecen como ignorados; solo hay valores de relleno en lo versionado

Tras las pruebas 9 y 10, restaura la clave y el certificado correctos.

5. Cambiar las claves usadas en pruebas

La clave del WiFi y la URL del túnel han aparecido en archivos que compartiste y en versiones anteriores del sketch. Cámbiala en el hotspot o router cuando termines las pruebas y actualiza secrets.h. Revisa también el historial de Git: si alguna versión anterior subió la clave, borrar el archivo ahora no la elimina del historial, y por eso conviene cambiarla.
